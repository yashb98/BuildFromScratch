1.The shape of the model — Config

Two non-obvious choices:

  • head_dim = 64 falls out of 576 / 9. Divisibility is the constraint that forced 9 heads — not the other way around.
  • intermediate_size ≈ 8/3 × hidden_size. SwiGLU has two up-projections (gate + up), so the inner width is shrunk from the usual 4× of a vanilla MLP to keep total parameter count comparable.

2.RMSNorm (lines 40–50)

t = x.float()
y = self.weight * t * torch.rsqrt(t.pow(2).mean(-1, keepdim=True) + self.eps)

LayerNorm subtracts the mean and divides by std. RMSNorm drops the mean subtraction: y = γ · x / √(mean(x²) + ε). Cheaper, and Zhang & Sennrich (2019) showed the centering does no useful work in transformers.

Two implementation details worth noting:

  • fp32 reduction. Even when activations are bf16, the squared sum is computed in fp32 (x.float()). 576 squared bf16 numbers summed in bf16 lose enough mantissa bits to drift; the inline comment on line 47 is doing real work — it's the kind of thing that silently breaks bit-exact parity with HF.
  • Bias-free, gain only. Modern Llama-family norms have only the multiplicative weight. No additive bias. Initial value is 1 (line 43) so the norm starts as identity.

3.RoPE — _rope, _rot, _apply (lines 53–67)

Rotary Position Embeddings encode position by rotating each (q, k) pair in 2D subspaces. Two equivalent formulations exist; this file uses the "duplicated" layout that matches HF's rotate_half, not the interleaved one in the original RoPE paper.

inv = 1.0 / (theta ** (arange(0, dim, 2) / dim))   # 32 frequencies for head_dim=64
f   = outer(arange(seq), inv)                       # (seq, 32) — angle per (pos, freq)
e   = cat([f, f], dim=-1)                           # duplicate to (seq, 64)
return e.cos(), e.sin()

_rot splits the head dim in half and swaps with a sign flip:

a, b = x.chunk(2, dim=-1)
return cat([-b, a], dim=-1)

_apply finishes the rotation: q' = q·cos + rot(q)·sin. Mathematically this is a complex multiplication q · e^(iθ) over each frequency pair, but expressed entirely in real tensors so the GPU never sees complex dtypes.

Why θ = 100,000? The base controls the wavelength of the slowest frequency, which sets how far positions can be reliably distinguished. The Llama-1 default was 10,000; bumping to 100,000 stretches the usable context — necessary for the 8,192-token window.

The cos/sin tables are precomputed once and registered as non-persistent buffers (lines 136–138). persistent=False means they're rebuilt from config on load instead of being saved in the state dict — which is why from_hf works with no key remapping.

4.Attention with GQA (lines 70–90)

self.nh, self.nkv, self.hd = 9, 3, 64
self.rep = self.nh // self.nkv  # = 3
self.q_proj = Linear(576, 9*64 = 576)
self.k_proj = Linear(576, 3*64 = 192)   # 1/3 the KV
self.v_proj = Linear(576, 3*64 = 192)
self.o_proj = Linear(576, 576)

GQA (Grouped-Query Attention) is the middle ground between MHA (nkv = nh) and MQA (nkv = 1). The 9 query heads partition into 3 groups; each group shares one K and one V head. The savings are entirely in KV-cache memory at inference — for a long context, KV cache dominates, and shrinking it 3× is the difference between fitting on a single GPU or not. Ablations in the Llama-2 paper showed it's near-lossless at this ratio.

The forward path:

  1. Project, reshape to (B, T, n_heads, head_dim), transpose to (B, n_heads, T, head_dim).
  2. Apply RoPE to Q and K only — V is position-free.
  3. repeat_interleave(rep, dim=1) materializes K and V back up to 9 heads. (At inference time you'd skip this and let SDPA broadcast; clarity over speed here.)
  4. F.scaled_dot_product_attention(..., is_causal=True) — PyTorch picks the best fused kernel (FlashAttention on Ampere+, mem-efficient elsewhere). The causal mask is free.
  5. Transpose back, flatten heads, project out.

No explicit /√d_k scaling appears because SDPA does it internally.

5.SwiGLU MLP (lines 93–101)

return self.down_proj(F.silu(self.gate_proj(x)) * self.up_proj(x))

A gated linear unit with SiLU (a.k.a. Swish) as the gate's activation. In equation form:

down( silu(W_gate · x) ⊙ (W_up · x) )

Two input projections (gate, up) and one output (down) — that's why the inner width is 1536 instead of the ~4×576 = 2304 you'd expect from a vanilla ReLU MLP: total params stay roughly matched.

Why SwiGLU beats gelu(W·x)? Empirically. Shazeer's "GLU Variants Improve Transformer" (2020) ablated it; SwiGLU has been the default in PaLM, Llama, Gemma ever since.

6.The block — pre-norm residual (lines 104–115)

x = x + self.self_attn(self.input_layernorm(x), cos, sin)
x = x + self.mlp(self.post_attention_layernorm(x))

Pre-norm (norm goes inside the residual branch, not after) is what makes deep transformers trainable without warm-up gymnastics. The residual path x → x → x is a clean identity highway; the normalized branch is what gets learned.

The two norms per block are independent: input_layernorm for attention input, post_attention_layernorm for MLP input. The HF name is slightly misleading — it sits before the MLP, not after attention's output.

7.Wiring it all together — SmolLM2 (lines 127–157)

self.model = _Stack(c)            # .embed_tokens, .layers, .norm
self.lm_head = Linear(576, 49152, bias=False)
if c.tie_word_embeddings:
    self.lm_head.weight = self.model.embed_tokens.weight   # SAME tensor

Weight tying (line 135): lm_head and embed_tokens share the same nn.Parameter object — not a copy. data_ptr() confirms a single 28.3M-parameter tensor backs both. This saves 28,311,552 params and is information-theoretically motivated: the mapping token → vector and vector → token should be inverses.

The HF compatibility trick Module names — model.embed_tokens, model.layers.{i}.self_attn.q_proj, model.norm, lm_head — are intentionally identical to transformers.LlamaForCausalLM. HF's safetensors load via load_state_dict with zero key remapping. The one wart: HF omits lm_head.weight from the state dict when tying is on; from_hf (lines 176–187) filters that key from missing before the assert.

Initialization (lines 139–142): std = 1/√hidden_size ≈ 0.0417 for every Linear and Embedding. This is the initializer_range from HF's config.json, copied literally so a from-scratch init matches what HF would produce.

9.Forward pass and training loss (lines 144–157)

x = embed_tokens(ids)
cos = rope_cos[:T]; sin = rope_sin[:T]      # slice precomputed table
for blk in layers: x = blk(x, cos, sin)
logits = lm_head(norm(x))

When labels is passed, it computes next-token CE loss with a one-position shift:

loss = cross_entropy(logits[..., :-1, :], labels[..., 1:])

The last logit has no target; the first token has no prediction. Standard causal-LM convention.

10.Sampling — generate (lines 159–174)

A minimal sampler. For each step:

  1. Slice the context to max_position_embeddings (8,192).
  2. Take logits at the last position.
  3. If temperature ≤ 0, argmax (greedy). Else divide by T, top-k truncate, softmax, multinomial.
  4. Append, repeat.

No KV cache — every step recomputes the full attention. Fine for verification (the project's purpose) and bad for production; model_full.py likely has the cached version.
